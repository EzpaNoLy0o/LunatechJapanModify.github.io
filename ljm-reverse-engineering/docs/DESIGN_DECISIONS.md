# 設計判断とライブラリ互換性調査

開発時に不明点・選択肢があった項目について、採用した判断と理由を記録します。

## 1. Python バージョンと依存ライブラリ（2026-11 調査）

PyPI の Windows (win_amd64) 用 wheel の有無を確認した結果:

| ライブラリ | 採用バージョン | cp311 | cp312 | cp313 | ライセンス | 備考 |
|---|---|---|---|---|---|---|
| PySide6(-Essentials) | 6.12.0 | ✔ (abi3) | ✔ | ✔ | LGPL-3.0 | GUI |
| VTK | 9.6.2 | ✔ | ✔ | ✔ | BSD-3 | cadquery-ocp 8.0.1 が `vtk==9.6.2` を要求 |
| PyVista / PyVistaQt | 0.49.2 / 0.13.2 | — | ✔ | ✔ | MIT | 純Python |
| SciPy | 1.18.1 | ✘ | ✔ | ✔ | BSD-3 | **cp312 以上のみ** |
| cadquery-ocp (OCP) | 8.0.1.1.0 | ✔ | ✔ | ✔ | Apache-2.0 (OCCT: LGPL-2.1+例外) | CAD カーネル |
| Open3D | 0.20.0 | ✔ | ✔ | ✔ | MIT | 任意（後述） |
| trimesh / shapely / ezdxf | 5.2.0 / 2.2.0 / 1.4.5 | ✔ | ✔ | ✔ | MIT / BSD / MIT | |

**判断: Python 3.12 (64bit) に固定。** すべての依存に Windows 用 wheel があり、SciPy 最新版の要件も満たす。
`requirements.txt` は直接依存をバージョン固定し、`requirements-lock.txt` に動作確認環境の完全な依存一覧を記録した。
クリーンな仮想環境に `requirements.txt` だけをインストールして全テストが通ることを確認済み。

## 2. CAD バックエンド: CadQuery ではなく OCP を直接使用

- CadQuery 2.8 は OCP に加え casadi・nlopt・multimethod 等の依存が多く、本アプリでは不要な機能が大半。
- 必要なのは B-Rep 生成・STEP 入出力・検証・テッセレーションのみで、OCP（OpenCASCADE の Python バインディング）で直接実装できる。
- 仕様の「互換性問題がある場合は独立した CAD バックエンドとして実装」に従い、`ljm_re/cad/occ_backend.py` に独立実装した。
  OCP 8 と 7.x の API 差（`TopoDS.Face` / `TopoDS.Face_s`、`OCP.collections` / `TColgp` など）は互換ヘルパで吸収している。
- OCP が無い環境ではアプリは起動し、CAD 関連のボタンのみ理由付きで無効化される。
- FreeCAD は使用していない（GUI 起動不要・依存削減のため）。

## 3. Open3D は任意依存にした

- Windows で **非 ASCII（日本語）パスのファイル読み書きに失敗する**既知の問題がある → ファイル I/O は trimesh（Python の open() を使用）で実装。
- インストールサイズが大きい（Linux 版は CUDA 込みで約 900MB）。EXE 同梱時の負担が大きい。
- フィッティング・ICP・法線推定・外れ値除去は NumPy/SciPy で独自実装し、決定的でテスト可能にした。
- Open3D がある場合のみ: 高速な法線推定、Poisson 表面再構成。無い場合は Poisson メニューが理由付きで無効化される。

## 4. 日本語パス対応

- メッシュ・CSV・DXF・プロジェクトは Python の I/O を経由（UTF-8 パス）。
- OCC のネイティブ I/O（STEP/BRep）は、Windows で非 ASCII パスの場合に ASCII の一時パスを経由する安全策を実装（`occ_safe_path`）。
- テストはすべて日本語を含むフォルダ名・ファイル名で実行している。

## 5. 座標・単位

- 内部単位は **mm**、角度は **度**。読込時に単位を確認させて mm に換算（STL は単位を持たないため）。
- 幾何要素はすべて**ワールド座標**で保持し、表示・編集・CSV 出力時に**作業座標系**へ変換。
- ビューは **Z 上**（自動車の座標系の慣例）。正面 = −Y 側から。
- 回転は「固定軸 X→Y→Z」(R = Rz·Ry·Rx)。

## 6. フィッティングのアルゴリズム

| 形状 | 手法 |
|---|---|
| 平面 | RANSAC（3点, 適応反復数）→ インライアで SVD 最小二乗を反復。閾値未指定時は残差 MAD から自動決定（使用値を記録）。面内軸は最小面積外接矩形の向き |
| 円筒 | 初期軸候補（法線共分散の最小固有ベクトル・法線付き2点 RANSAC・主成分）→ 軸直交投影の Taubin 円 → 5 パラメータの Levenberg-Marquardt → インライア再判定。ヤコビアンから半径・軸角度・軸位置の 1σ を推定、円周カバー範囲・軸長で警告 |
| 円 | Taubin（代数）→ 幾何距離 LM、任意で 3 点 RANSAC。3D 円は平面フィット後に投影 |
| 球 | 代数初期値 → LM → トリミング |
| 穴中心 | 円筒軸 ∩ 基準平面 / 平面から深さ d の断面ループの円フィット / 自動検出（円形閉ループ） |

不確かさの推定値は合成データで実際の誤差とよく一致することを確認した（IMPLEMENTATION_STATUS.md の精度表）。

## 7. 断面とスケッチ

- メッシュと平面の交点を**エッジ単位で一意に識別**し、位相で連結（許容誤差に依存しない）。
- スケッチ化は split-and-fit（弦の偏差 → 3点円弧 → 最大偏差点で分割）+ 統合（統合後も元の点列で再検証）。
  端点は元のポリラインの点を共有するため、閉じた輪郭は必ず閉じたワイヤーになる（押し出し可能）。

## 8. 非破壊編集と Undo

- メッシュ編集は常に新しい配列を返し、既存配列を書き換えない → Undo のスナップショットは配列の参照だけで済む（メモリ効率）。
- 読込時の元データ `original_V/F` と累積の剛体変換 `pose` を保持。「オリジナルに戻す」は位置合わせを保ったまま編集だけを破棄。
- 穴埋めで生成した面は面フラグ `FLAG_ARTIFICIAL` で区別し、表示（ピンク）・フィット除外・CSV に反映。
- Undo は Qt 非依存のコマンドスタック（`model/undo.py`）。表示/非表示の切替は Undo 対象外（CAD ソフトの一般的な挙動）。

## 9. GUI

- 「上部ツールバー」は、メニューバー + カテゴリ別タブのリボン（仕様のカテゴリ名そのまま）で実装。
- マウス: 右ドラッグ回転・中ドラッグパン・ホイールズーム。左ボタンは選択ツールに割り当て（ツール無しでは回転）。
  選択操作と視点操作を同時に行えるようにするため（Revo Design / Design X 系の操作感を参考に独自実装）。
- 長時間処理は `QThreadPool` のワーカーで実行し、進捗とキャンセルをステータスバーに表示。結果のドキュメント反映は必ずメインスレッドで行う。
- VTK の標準フォントは日本語に対応しないため、3D ビュー内のラベルは英数字（例: `55.000 mm`）。日本語はツリー・プロパティに表示。
- 大規模メッシュ: 面数が閾値（既定 400 万）を超えると表示用 LOD（vtkQuadricClustering）を使い、選択・計算は元の解像度で行う。

## 10. プロジェクトファイル

`.ljmre` = ZIP（`project.json` + `arrays/*.npz` + `cad/*.brep`）。元スキャンファイルのパスと SHA-256 を記録し、
メッシュ自体（元データ・編集後）もアーカイブに保存するため、元ファイルが移動・削除されても作業を継続できる。
保存は一時ファイルに書いてから置き換える（書込み途中の失敗で既存ファイルを壊さない）。形式バージョンを記録。

## 11. STEP 出力

- XCAF（STEPCAFControl）で形状ごとに名前を付けて出力（名前は STEP 互換性のため ASCII 文字のみ。非 ASCII は除去）。失敗時は通常の STEPControl にフォールバック。
- 単位 mm、スキーマ AP214（AP242 も選択可）。
- 出力後に再読込し、面の種類と数・ソリッド数・体積・表面積・外形（厳密 bbox）・円筒/球の半径を比較して検証。
- 基準点は STEP で自由頂点として扱われにくいため、CSV/JSON（`*_datums.*`）で出力。基準軸・穴はエッジとして STEP に含めることもできる。
