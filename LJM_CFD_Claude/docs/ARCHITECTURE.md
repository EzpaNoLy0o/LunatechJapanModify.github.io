# LJM CFD (Claude Edition) — アーキテクチャ設計

Windows 11 で動作する自動車専用 CFD ワークベンチの全体設計です。
Stage 1〜6 を通して変わらない骨格と、各ステージで追加するモジュールを定めます。

- **実装済み**: Stage 1（GUI・3D 表示・CAD 読み込み・モデル操作・形状検査）、Stage 2（仮想風洞・メッシュ生成・品質評価・polyMesh 変換）、Stage 3（OpenFOAM 連携・解析・荷重・収束判定）、Stage 4（流れ場の可視化）、Stage 5（スライダー操作・粒子アニメーション）
- **未実装**: Stage 6（本書の該当節は「設計」であり、動作するコードはまだありません）

---

## 1. 設計方針

| 方針 | 具体策 |
|---|---|
| 計算と可視化の分離 | 重い処理はすべて **子プロセス（ジョブ）** で実行し、結果はファイルで受け渡す。GUI は結果ファイルを読むだけ |
| GUI を止めない | CAD 変換・メッシュ生成・ソルバー起動は `QProcess`。OpenCASCADE は GIL を解放しないため、スレッドではなくプロセスを使う |
| 偽の結果を出さない | 値が無いものは「未計算」「計算失敗」と表示する。既定値・推定値で埋めない |
| エラーを握りつぶさない | 想定内のエラーは `JobError`（日本語メッセージ）、想定外はトレースバックごとログへ。未捕捉例外は `sys.excepthook` で記録 |
| Windows ⇔ WSL のパス問題を作らない | パス変換は `core/paths.py` に一元化。作業フォルダは ASCII パス（`C:\LJM_CFD_Claude\workspace`）に固定 |
| 拡張しやすさ | ジョブはレジストリ登録制、プロジェクト JSON は未知キーを保持、メッシャー／ソルバーはバックエンド差し替え可能な構成 |

## 2. プロセス構成

```
│   ├ cad-import   STEP/IGES/STL → キャッシュ   [Stage 1 実装済] │
│   ├ cad-inspect  形状検査                     [Stage 1 実装済] │

```

### ジョブ・プロトコル（`core/jobs.py`）

子プロセスは標準出力へ `@@LJMJOB@@ {json}` の行を出します。

| type | 内容 |
|---|---|
| `progress` | `value`（0〜1）と `message` |
| `log` | ログ 1 行 |
| `event` | 逐次データ（残差・荷重の履歴など）。`name` と `data` |
| `result` | 成功時の結果（最後に 1 回） |
| `error` | 失敗時のメッセージと詳細 |

それ以外の行（OpenCASCADE や OpenFOAM の生出力）は通常ログとして扱います。
ジョブ関数は `func(args: dict, ctx: JobContext) -> dict` という素の Python 関数なので、
テストからはプロセスを起こさず直接呼べます。新しいジョブは `JOB_REGISTRY` に 1 行足すだけです。

## 4. 座標系と規約（全ステージ共通）

| 項目 | 規約 |
|---|---|
| 風向 | 常にグローバル **+X**。相対風向は車両側の姿勢で与える |
| 上方向・地面 | **+Z** が上、地面は **Z = 0** |
| 車両の向き | ノーズを **−X**（上流）へ向ける。車両左側面は −Y |
| 内部単位 | 長さ m、速度 m/s、圧力 Pa（SI）。表示単位（mm / m）は書式だけに影響 |
| 回転 | 右手系・度。`R = Rz(yaw) · Ry(pitch) · Rx(roll)` |
| 荷重の符号（Stage 3） | Drag = +X 方向の力、Lift = +Z 方向の力、**Downforce = −Lift**。GUI では両方を別の行で表示する |

### 2 段階の変換

```
x_world = A · P_i · (s_i · x_local)
```

- `s_i` … パーツのファイル単位 → m
- `P_i` … パーツ個別の配置（回転中心 = パーツ自身の境界ボックス中心）
- `A`  … 車両全体の姿勢（回転中心 = 全体境界の XY 中心・最下点）

VTK アクターの変換行列だけを書き換えるため、移動・回転でメッシュを作り直しません。
Stage 2 のメッシュ生成では同じ行列を B-Rep / STL へ適用して風洞内に配置します。

## 5. データの流れ

```
CAD ファイル ─(cad-import ジョブ)→ workspace\cache\cad\<key>\
                                    ├ meta.json          パーツ一覧・単位・統計
                                    ├ part_NNN.vtp       表示メッシュ（面番号つき）
                                    ├ part_NNN_edges.vtp 面輪郭線
                                    ├ part_NNN_hull.npy  凸包頂点（境界計算用）
                                    └ part_NNN.brep      B-Rep（Stage 2 の入力）
                                          │
            [Stage 2] mesh-generate ジョブ ▼
                       projects\<名前>\mesh\   メッシュ + 品質レポート(JSON)
                                          │
            [Stage 3] solver-run ジョブ    ▼
                       projects\<名前>\case\   OpenFOAM ケース（WSL で実行）
                       projects\<名前>\results\ forces.csv / residuals.csv / *.vtu
                                          │
            [Stage 4-5] GUI（post\）       ▼
                       断面・流線・粒子 … 読み込んだ結果から GUI プロセス内で生成（再計算なし）
```

キャッシュのキーは「元ファイルの絶対パス・サイズ・更新時刻・品質・インポータ版」です。
同じファイルは即座に開き、ファイルが更新されれば自動で再変換されます。

### 単位の扱い

- **STEP / IGES**: OpenCASCADE が読み込み時に mm へ換算。元ファイルの単位は別途検出して表示（情報）。
- **STL**: 単位を持たないため寸法から推定し、**「推定」であることを明示**。GUI で変更可能。

## 6. ステージ別の設計

### Stage 1 — 実装済み
本書 2〜5 節のとおり。詳細は README を参照。

### Stage 2 — 実装済み

- **風洞** (`tunnel/spec.py`): モデルのワールド境界から計算領域を決める。地面は常に Z = 0。
  解析モードごとの既定値（車両: 前 3L / 後 6L / 左右 3W / 上 4H、地面あり。単体: 各方向 3D〜6D、地面なし）。
  Internal Flow は定義のみで、選択不可・検証でエラーになる。
- **前面投影面積** (`tunnel/frontal_area.py`): 三角形を YZ 平面へ投影して高解像度画像へ塗りつぶし、重なりを除いた面積を求める。
  閉塞率と Cd・Cl の基準面積に使う。未計算の間は閉塞率も基準面積も「未計算」。
- **メッシュ生成** (`mesh/gmsh_job.py`):
  1. キャッシュ B-Rep を OCC カーネルへ読み込み、相似変換（拡大・回転・移動）で配置。
     アフィン変換は曲面を NURBS 化して精度と速度を落とすため使わない。
  2. 風洞ボックスからモデルを差し引いて流体領域を作る（地面より下・パーツの重なりは自動的に処理される）。
  3. 外周面は位置で分類、残りはサンプル点から各パーツ表面への距離でパーツへ対応付け、パーツごとの壁面パッチにする。
  4. サイズ場 = 表面からの距離（パーツ別倍率）・接地線まわり・後流ボックスの最小値 + 曲率。
  5. 四面体は並列 HXT、失敗時は逐次 Delaunay へ自動で切り替え。
- **接地の扱い**: 最下点が Z ≈ 0 のモデルは `contact_sink`（既定 10 mm）だけ沈めて有限の接地面を作る。
  半径 330 mm のタイヤでは 5 mm だと接地端が約 10° のくさびになり品質警告が残る。10 mm で非直交性 70° 未満になる。
- **polyMesh 変換** (`mesh/polymesh.py`): 自前実装。面の対応付けは節点集合の辞書式ソートで行い、
  OpenFOAM の順序規約（内部面は owner → neighbour の昇順、法線は owner → neighbour、境界面はパッチごと）に従う。
  四面体・プリズム・ピラミッド・六面体に対応。
- **品質評価** (`mesh/quality.py`): OpenFOAM の checkMesh と同じ定義の非直交性・歪度、負体積、開いたセル、
  外周の閉じ具合、CAD の流体体積との差。**OpenFOAM 実機の checkMesh との突き合わせは Stage 3 で行う。**
- **境界層プリズム（実験的）**: Gmsh の `extrudeBoundaryLayer`。モデルが地面・壁に接していない場合のみ。
  面の法線が流体側を向いているかを実際に調べて押し出し方向を決め、生成後に
  「プリズム数 = 層数 × 壁面の面数」「メッシュ体積と CAD 体積の差がプリズム体積の半分未満」を検証する
  （内側へ押し出されると体積がプリズム体積の 2 倍増えるため検出できる）。
  条件を満たさなければジョブを失敗させ、境界層なしのメッシュへ黙って切り替えない。
- **メッシュの鮮度**: 形状・姿勢・風洞・設定から入力ハッシュを作り、レポートに記録。現在の状態と一致しなければ「再生成が必要」。
- **未対応**: STL パーツの体積メッシュ、半分モデル（対称面）、接地形状の境界層。
  `snappyHexMesh` バックエンドは OpenFOAM が必要なため Stage 3 以降で検討する。

### Stage 3 — 実装済み

- **実行環境** (`solver/environment.py`): Windows では `wsl.exe -d <distro> -- bash <script>`、Linux では `bash <script>`。
  コマンドは必ず「ケースフォルダに書いた LF 改行のシェルスクリプトを実行する」形にする。
  Windows → wsl.exe → bash と引数を渡す途中で引用符や `$` が壊れるのを避けるため。
  ケースは `/mnt/c/...`（プロジェクトフォルダ）で直接実行するので、結果のコピーは不要。
  `wsl.exe` 自身のメッセージは UTF-16LE なので、UTF-8 として読めない場合は UTF-16LE として読む。
- **ケース生成** (`solver/case.py`): OpenFOAM 14 付属チュートリアル（`incompressibleFluid/drivaerFastback`）の書式に合わせ、実機で確認済み。
  `foamRun` + `incompressibleFluid`、k-ω SST、`steadyState`。
  対流 `bounded Gauss linearUpwind limited`、勾配 `cellLimited Gauss linear 1`、拡散 `Gauss linear limited corrected 0.5`。
  壁面は `nutUSpaldingWallFunction`（全 y+ 域で有効）。
- **実行手順** (`solver/run_job.py`): `checkMesh` → `renumberMesh` → `potentialFoam` → （`decomposePar`）→ `foamRun` →（`reconstructPar`）→ `foamToVTK`。
  - `renumberMesh`: Gmsh の並列メッシャーはセルの並びが空間的にばらばらで、行列の帯幅が非常に大きい（34 万セルで 337,158）。
    並べ替えると 7,766 になり、ソルバーが約 3 割速くなる（実測 1.25 → 0.85 秒 / 反復）。
- **監視**: 実行中に `postProcessing/` の残差・荷重ファイルを追記分だけ読み、`event` として GUI へ送る。
- **停止**: `stopAtFile` function object を使う。GUI がケースフォルダに `stop` ファイルを置くと、
  OpenFOAM がその反復の結果を書き出して終了する（途中結果として読める）。プロセス間通信は不要。
  アプリ終了時などの強制終了では、ジョブとその子プロセスをまとめて止める（POSIX はプロセスグループ、Windows は `taskkill /T`）。
- **続きから**: `startFrom latestTime` と `endTime` の更新。荷重・残差の履歴は開始時刻ごとのフォルダに分かれるので、読み込み時につなぐ。
- **収束判定** (`solver/convergence.py`): 「計算完了」と別に、荷重の安定（変動幅と前半・後半の差）、最終残差、質量収支で判定する。
  しきい値は同ファイルの定数と README に記載。残差が打ち切り基準に達して終了した場合も、それだけでは「収束」としない。
- **結果** (`solver/results.py`): 荷重は直近区間の平均。圧力成分と粘性成分を分けて保持。
  係数は基準面積がある場合のみ計算し、GUI は「現在の」基準面積で換算し直す。パーツ別の荷重、実測 y+、場の範囲、精度の注意書きを付ける。
- **失敗時**: ソルバーの異常終了・発散は `status = failed` として記録し、荷重の値は入れない。GUI は「計算失敗」と表示する。
- **結果の鮮度**: メッシュのハッシュ・流れの条件・地面の扱い・ソルバー設定から入力ハッシュを作る（基準面積と並列数は含めない）。
- **検証**: OpenFOAM 14 の `checkMesh` が自前の `polyMesh` を「Mesh OK」と判定し、非直交性・歪度・体積の値が自前の品質評価と一致する（自動テストで確認）。
  Ahmed ボディ（粗い四面体・境界層なし）で Cd = 0.352（文献の実験値 0.285）。
- **未確認**: Windows + WSL2 での実行（`wsl.exe` 経由の起動、`/mnt/c` 上の実行速度、WSL 内の非 root ユーザーでの `mpirun`）。

### Stage 4 — 実装済み

- **結果の読み込み** (`post/result_set.py`): `fields.vtu`（節点値のみ・無圧縮。34 万セルで読み込み約 0.4 秒）と壁面の `surface/*.vtp`。
  抽出フィルタは入力の全配列を補間するので、速度ベクトルとスカラー量だけを持つ軽いコピーを使う。
- **断面**: `vtkPlaneCutter` を使い回し、平面の位置だけを変える（34 万セルで 1 回 約 15 ms）。
  GUI 側 (`gui/post_view.py`) はアクターを作り直さず、同じメッシュの中身を差し替える。
- **流線**: `vtkStreamTracer`（RK45、セルロケータ）。開始点は X 軸に垂直な長方形の面上の格子。96 本で約 0.2 秒。
- **等値面**: `vtkContourFilter`。他の物理量も補間して色付けに使う。
- **カラースケール**: 物理量ごとに 1 つ（レイヤー間で共有）。既定範囲は上下 0.5 % を除いた分位点。
  カラーバーの見出しは VTK の既定フォントで表示できる ASCII のみ（日本語は GUI 側のラベルで示す）。
- **表示の約束**: 結果が無ければ何も描かない。値が範囲外で面が存在しなければ面を描かない。
  表面分布の表示中は、重なる CAD 形状を隠す。
- **テスト**: 解析的に値の分かる合成データ（`tests/synthetic.py`）で、断面が平面上にあること・値の補間・流線が速度場に沿うこと・
  等値面の位置を確認。OpenFOAM が無い環境（Windows）でも実行できる。実物の OpenFOAM の結果でも全レイヤーを確認。

### Stage 5 — 実装済み（スライダー操作・今回の最重要機能）

- **操作バー** (`gui/flow_bar.py`): 3D ビューの直下。断面・流線の開始位置・タイムラインの 3 本のスライダーを別々の行に置く。
  バーは設定を持たず、`PostView` の設定を表示・変更するだけ（右の「可視化」タブと常に同じ値を示す）。
  バーの最小幅が中央の領域を押し広げて左右のパネルを潰さないよう、注記は折り返し、最小幅は約 600 px に抑える。
- **断面スライダー**: `PostView.set_slice_position()`。`vtkPlaneCutter` の平面位置だけを変え、表示中のメッシュの中身を差し替える
  （アクターは作り直さない）。34 万セルで 1 回 約 15 ms なので、間引き表示は不要だった。
- **流線の開始位置スライダー**: `PostView.request_seed()`。流線の引き直しは約 0.2 秒かかるので、ドラッグ中に届いた途中の値はまとめ、
  イベントループへ戻った時点の最新値だけを処理する。
- **粒子・スモーク** (`post/particles.py`): `AnimationSource`（抽象）と `SteadyPathlines`（定常場）。
  流跡線を等間隔の「経過時間」で標本化した配列（流線数 × 300 点）を持ち、時刻 t の粒子位置は添字計算と線形補間だけで求める。
  - 同じ時刻には必ず同じ位置を返す → タイムラインを戻せば粒子は正確に元へ戻る。逆再生も同じ計算。
  - 粒子 k の放出時刻は `k · duration / 粒子数`。ループ再生では経過時間を `duration` で折り返すので切れ目なく流れる。
  - タイムラインの長さは「80 % の流線が終点へ届く時間」。後流に捕まって回り続ける流線に全体を引き延ばされないため。
  - 配列の長さは時刻によらず一定。見えない粒子は透明にして軌跡の始点・終点に留める（表示側は座標と色の書き換えだけ）。
  - スモークは粒子ごとの尾を折れ線で結び、後ろほど透明にして描く。粒子は点（球）で描く。
- **キャッシュ** (`PostView.animation()`): 流跡線（重い）は結果と開始面が同じ間、標本化（軽い）はさらに密度・表示形式が同じ間、使い回す。
  時刻・再生速度・ループの変更では何も作り直さない。**どの操作でも OpenFOAM は実行しない。**
- **定常解析であることの明示**: `AnimationSource.is_steady` が真のとき、操作バーに日本語の注記を、3D ビュー内に英語の注記
  （VTK の既定フォントで表示できる ASCII。スクリーンショットと書き出した動画にも残る）を必ず表示する。
- **再生**: 33 ms 間隔のタイマーで実時間を測り、`advance(実時間)` でタイムラインを進める（再生速度 × 1 で全体を 8 秒）。
  描画が遅い環境でもコマを落とすだけで、再生時間は変わらない。
- **描画**: `Viewport.request_render()` はウィジェットの再描画を 1 回だけ依頼する。`plotter.render()` は
  「描画 → 再描画イベント → もう一度描画」と 1 コマに 2 回描くため、アニメーションの滑らかさが半分になっていた。
- **書き出し** (`MainWindow.export_animation`): タイムライン 1 周を等分した時刻ごとに 3D ビューを撮影し、GIF（Pillow）または PNG 連番で保存。
- **将来の非定常対応**: 時刻ごとの速度場から粒子を進める `AnimationSource` を追加すれば、GUI 側（操作バー・再生・書き出し）は変更不要。
- **テスト**: 合成データ（流速が高さだけで決まる）で、粒子の進んだ距離 = 流速 × 時間、巻き戻しで同一位置、ループの継ぎ目、
  スライダー同士の独立、ドラッグのまとめ処理、流線を積分し直さないこと、ジョブが起動しないこと、書き出し、保存・復元を確認。
  実物の OpenFOAM の結果でも、粒子が物体を避けて下流へ進むことを確認。

### Stage 6 — 保存・出力・配布（設計）

- 結果の CSV / レポート出力、PyInstaller による配布形態（動画書き出しは Stage 5 で実装済み）。

## 7. 精度に関する取り決め

1. 計算していない値・取得に失敗した値は表示しない（「未計算」「計算失敗」）。
2. 指定反復数の終了は「計算完了」であって「収束」ではない。収束判定は残差・荷重変動・質量収支で別に行う。
3. 境界層メッシュの有無と解像度を結果に必ず併記する。
4. 閉塞率・風洞余白・メッシュ密度など、結果の信頼性に影響する条件をレポートへ残す。
5. 検証形状として Ahmed ボディ（`scripts/make_demo_models.py`）を用意し、Stage 3 以降で文献値と比較する。

## 8. テスト方針

| 種類 | 内容 |
|---|---|
| 単体テスト | 単位・姿勢・パス変換・プロジェクト JSON・単位検出 |
| 処理テスト | OCP で生成した試験形状（直方体・アセンブリ・開いたシェル・IGES・STL）を実際に読み込み検査 |
| ジョブ経路 | GUI と同じ `python -m ljmcfd --job …` を子プロセスとして実行 |
| GUI 結合テスト | 実ウィンドウを開き、読み込み → クリック選択 → 面選択 → 計測 → 姿勢変更 → 検査 → 保存 → 再読み込み |

各ステージで「試験形状に対して実際に処理が通ること」を確認し、未確認の環境（特に Windows 実機）は未確認と報告します。
